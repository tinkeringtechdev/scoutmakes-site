# ScoutMakes — Astro site: test, deploy, cutover

## What's in this package

- `src/pages/` — Home, three product pages (FM Radio Board, FM Radio Kit, Robot Kit), two assembly-instruction
  guides, a Learn index, About, and Contact — rebuilt from the current scoutmakes.com Shopify store (fetched
  July 2026).
- No cart/checkout — product pages link out to Adafruit, Tindie, and The Pi Hut instead, per your call to have
  distributors handle sales.
- `.github/workflows/deploy.yml` — builds the site and FTPs it to GoDaddy on every push to `main` (staging), or
  on demand to production via the Actions tab.

This was hand-built directly (not generated by `npm create astro`) because this sandbox has no package
registry access to run `npm install` here. Verify the build once on your own machine before pushing — see Step 1.

## Known gaps to fix before cutover

  port to a static site. I put in a placeholder `hello@scoutmakes.com` mailto link — swap in your real address,
  or wire up a form service (Formspree, Getform) if you'd rather not publish an email directly.
- **Robot Kit product page** — the live page 404'd on direct fetch (Shopify may have archived/region-gated it);
  content was reconstructed from search-engine cache. Double check it against your Shopify admin for anything
  I might have missed.
- **About Us page** — same situation as Robot Kit (404 on direct fetch, recovered via cache). It's a short
  page, so likely complete, but worth a quick glance.
- **Images** — none of the original product photos came through search/fetch. Pull the images you want
  (product photos, assembly-step photos, board renders) from Shopify's admin media library and drop them into
  `public/images/`, then reference them in the relevant `.astro` pages.
- **Distributor links** — I linked to Adafruit's, Tindie's, and The Pi Hut's storefronts generally; swap in the
  exact product URLs if you want direct links to each listing.

## Step 3 — Set up GoDaddy FTP credentials as GitHub Secrets

Static output, no PHP/database needed — GitHub Actions builds it, then FTPs `dist/` straight into the target
directory on GoDaddy.

1. In GoDaddy cPanel → FTP Accounts, create (or find) an FTP user scoped to your hosting account.
2. Decide your staging location — either a subdomain (e.g. `staging.scoutmakes.com`, created in cPanel →
   Subdomains) or a subfolder under `public_html`. Note its document root path.
3. In your GitHub repo → Settings → Secrets and variables → Actions, add:
   - `FTP_SERVER` — the server hostname cPanel shows on the FTP Accounts page.
   - `FTP_USERNAME`
   - `FTP_PASSWORD`
   - `STAGING_SERVER_DIR` — document root for your staging subdomain/subfolder, e.g. `/public_html/staging/`.
   - `PROD_SERVER_DIR` — document root for the live domain, e.g. `/public_html/`.
4. Push to `main` to trigger the staging deploy automatically. Check the staging URL before doing anything else.
5. When staging looks right, go to the Actions tab → this workflow → **Run workflow** → choose `production` to
   deploy to the live directory (still behind the old DNS until Step 4 below).

## Step 4 — DNS cutover from Shopify to GoDaddy

Do this only after the production FTP deploy has succeeded and you've checked it on GoDaddy's hosting URL.

1. Check whether scoutmakes.com currently has any mailboxes or MX records tied to Shopify or a third-party
   provider — note them before touching anything.
2. In GoDaddy → My Products → DNS, either point the domain's A record to GoDaddy's hosting IP, or change
   nameservers to GoDaddy's if it's now the full DNS host.
3. DNS propagation can take a few minutes to 48 hours — check with `dig scoutmakes.com` or whatsmydns.net.
4. Keep the Shopify store reachable (or at minimum note its settings) for a few days after cutover, in case you
   need to roll back.
5. Once stable, cancel/downgrade the Shopify plan.
